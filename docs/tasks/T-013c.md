## T-013c — Giriş akışı blokerleri: `code` kaybı, kurtarma kodu yolu, kilit bağlantısı

**Ajan:** Backend | **Öncelik:** P0 | **Bağımlılık:** T-013b, T-014, T-017
**Faz:** F1 — Veri & Auth
**Kaynak:** T-017 → ENGEL-1, ENGEL-2 · T-014 → BULGU-005
**PROGRAM.md referansı:** §7.2, §8.4, §8.19 · **ADR:** 013, 022

**Amaç:** Giriş akışı üç ayrı yerde kopuk. Üçü de küçük ama üçü de akışı **fiilen
çalışmaz** kılıyor: 2FA'lı kullanıcı giriş yapamıyor, kurtarma kodu yolu ölü kod, ve
§8.4 kilitleme politikası hiçbir zaman tetiklenmiyor. Frontend ve Güvenlik tarafları
hazır ve bekliyor.

**Üçü de Orkestra Şefi tarafından depoda doğrulandı.**

---

### ENGEL-1 (P0) — `code` istemciye hiç ulaşmıyor

`src/server/auth.ts:147` → `class CredentialsError extends Error` ve `this.name` elle
`'CredentialsSignin'` yapılıyor. Auth.js ise **`instanceof`** kontrolü yapıyor:

```js
// @auth/core/index.js
if (error instanceof CredentialsSignin) params.set("code", error.code);
```
Düz `Error` bu kontrolü geçemediği için `CallbackRouteError`'a sarılıyor; istemciye
`error=Configuration` gidiyor, `code` **hiç gitmiyor**. Sonuç: `TOTP_REQUIRED` ulaşmıyor →
ikinci adım hiç açılmıyor → **2FA'lı kullanıcı giriş yapamıyor.** Üç hata kodu da ayırt
edilemiyor.

**Düzeltme (Frontend tarafında değişiklik gerekmiyor):**
```ts
import { CredentialsSignin } from 'next-auth';
class CredentialsError extends CredentialsSignin {
  constructor(code: string) { super(code); this.code = code; }
}
```

### ENGEL-2 (P0) — Kurtarma kodu yolu şema tarafından kapatılmış

`src/lib/schemas/user.ts:65` → `loginSchema.totpCode = totpCodeSchema.optional()`,
`totpCodeSchema` ise `/^\d{6}$/`. `src/server/auth.ts` her isteği `loginSchema` ile
doğruladığı için `ABCDE-FGHIJ` biçimi `authenticateUser`'a **hiç ulaşmadan**
`INVALID_CREDENTIALS` oluyor. `credentials.ts` içindeki `verifyTotpWithRecovery`
kurtarma kodunu destekliyor — yani ADR-013'ün kurtarma yolu şu an **ölü kod**.

**Düzeltme:** `src/lib/schemas/user.ts`'e paylaşılan
`loginCodeSchema = z.union([totpCodeSchema, totpBackupCodeSchema])` eklenip
`loginSchema.totpCode` bunu kullanacak. Frontend aynı birleşimi geçici olarak kendi
tarafında kurdu (T-017/K1) ve bu yayınlanınca kendi kopyasını silecek — §7.3 tek kaynağa döner.

### BULGU-005 (Yüksek) — Kilitleme politikası bağlanmamış

T-014 `applyLockoutPolicy`'yi yazdı ve 20 testle doğruladı, ama **çağıran üretim kodu yok**;
`lockedUntil` hiçbir yerde yazılmıyor. §8.4 bu yüzden ⚠️. Giriş akışı `src/server/auth/**`
altında ve Güvenlik ajanının yazma izni yok (§10.1). İki kalem:

1. `AuthClient.user.update` girdi tipi `lockedUntil?: Date` kabul etsin — bugün tip düzeyinde yazılamıyor
2. `authenticateUser` içindeki `fail()`, `recordLoginAttempt`'ten **sonra** `applyLockoutPolicy` çağırsın
   — **sıra önemli:** tetikleyen deneme sayıma girmeli

Tam kod parçası `docs/security/README.md` → BULGU-005'te.
