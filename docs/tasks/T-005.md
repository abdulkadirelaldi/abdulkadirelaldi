## T-005 — GitHub Actions CI hattı, Lighthouse CI, Node 22 sabitlemesi

**Ajan:** Güvenlik & Test | **Öncelik:** P0 | **Bağımlılık:** T-003c, T-004
**Faz:** F0 — Temel
**PROGRAM.md referansı:** §8.18 (gizli bilgi taraması), §8.24 (`npm audit` kapısı), §9 (test ve performans eşikleri), §10.5, §10.6 (DoD)
**İlgili ADR:** ADR-003 (pnpm), ADR-006 (`postinstall`), ADR-008 (Node 22), ADR-009 (GitHub Actions)

**Amaç:** F0'ın son parçası. §10.6'nın "hepsi sağlanmadan tamamlandı sayılmaz" kuralını
otomatik bir kapıya bağlamak; §8.18 ve §8.24'ü ilk kez fiilen uygulamak. Node sürümü
tek kaynaktan sabitlenerek "yerelde çalışıyor, CI'da çalışmıyor" sınıfı hatalar önlenir.

**Kapsam (dokunulacak):**
- `.github/workflows/ci.yml` — ana kapı
- `.nvmrc` — `22` (ADR-008 tek kaynağı)
- `package.json` — **yalnızca** `engines.node` → `">=22.11.0"` (ADR-008 yetkilendirmesi)
- `lighthouserc.json` (veya eşdeğeri) — §9 eşikleri
- `tests/unit/db.test.ts` — tembel kurulum ve eksik `DATABASE_URL` davranışı (T-003c/T4 önerisi)
- `docs/security/README.md` — §8 tablosunun güncellenmesi, BULGU-002 kapanışı

**Kapsam dışı (DOKUNULMAYACAK):**
- `src/server/**`, `src/app/api/**`, `prisma/**`, `prisma.config.ts` — Backend'in (okunur, düzenlenmez)
- `src/app/(public)/**`, `src/app/(panel)/**`, `src/components/**`, `src/app/globals.css`, `src/app/layout.tsx`, `src/app/page.tsx` — Frontend'in
- `next.config.ts`, `tsconfig.json`, `eslint.config.mjs`
- `package.json`'da `engines` dışındaki alanlar (`dependencies`, `scripts`)
- `Dockerfile` — T-070
- Nonce tabanlı CSP — F6/T-060

**Kabul kriterleri:**
- [ ] `.nvmrc` = `22`; `package.json` `engines.node` = `">=22.11.0"`; CI `node-version-file: .nvmrc` okuyor — üç yer sapmıyor
- [ ] CI sırası: `install → lint → typecheck → test → build → test:e2e`; herhangi biri düşerse iş kırmızı (§10.6)
- [ ] CI'da **`.env` yok** ve **Postgres servisi yok** — hat yine de yeşil (T-003c ile mümkün oldu)
- [ ] pnpm önbelleği yapılandırılmış; `pnpm install --frozen-lockfile` kullanılıyor
- [ ] Kapsam raporu CI'da üretiliyor; eşik `COVERAGE_ENFORCE` ile kontrol ediliyor (F1'de zorunlu kılınacak)
- [ ] Playwright tarayıcıları CI'da kuruluyor ve E2E geçiyor
- [ ] **§8.24:** `pnpm audit` adımı var; yüksek/kritik açıkta iş kırmızı
- [ ] **§8.18:** `NEXT_PUBLIC_*` değişkenlerinde sır taraması adımı var ve fiilen çalışıyor
- [ ] Hiçbir adımda gerçek `DATABASE_URL` secret'ı kullanılmıyor (BULGU-002'nin işaret ettiği refleks)
- [ ] Lighthouse CI yapılandırıldı: Performance ≥ 90, Accessibility ≥ 95, Best Practices ≥ 95, SEO ≥ 95 (§9)
- [ ] Lighthouse **F0'da uyarı modunda** (`warn`), F2 sonunda `error`'a çevrilecek — public sayfalar henüz yok
- [ ] `tests/unit/db.test.ts`: (a) modül import edilince havuz kurulmuyor, (b) `DATABASE_URL` eksikken ilk erişimde hata fırlıyor, (c) hata mesajında değer/host yok (§8.20)
- [ ] `docs/security/README.md`'de BULGU-002 **kapalı** olarak işaretli, §8 tablosu güncel
- [ ] Yerelde `pnpm lint && pnpm typecheck && pnpm test && pnpm build` temiz

**Test:** `tests/unit/db.test.ts` (yukarıda). CI'ın kendisi de doğrulanmalı — hattın
yeşil geçtiği ve **bilerek bozulduğunda kırmızı olduğu** raporda gösterilmeli.

**Dışarıya sözleşme (raporda mutlaka belirtilecek):**
- CI iş adları ve sırası; hangi adım neyi garanti ediyor
- Bir ajanın CI'ı yeşil tutmak için yerelde koşması gereken tam komut zinciri
- `.nvmrc` / `engines` / CI üçlüsünün nasıl senkron tutulduğu
- Lighthouse eşiklerinin ne zaman `error`'a çevrileceği
- §8'in 25 maddesi için güncel durum tablosu
