## T-044g — Dört rota beyanı (paralellik boşluğu) + F3 kapanış denetimi

**Ajan:** Güvenlik & Test | **Öncelik:** P0 — **PR #13'ü BLOKLUYOR**
**Faz:** F3 — Panel Çekirdek | **Bağımlılık:** T-043f
**PROGRAM.md referansı:** §8.20, §9 | **İlgili ADR:** 028, **034 (yeni)**

### 1. Dört rota beyanı — merge'i bu blokluyor

**Hatan değil, benim sıralamamın sonucu.** T-043g ile T-043f paralel koştu; sen iki
mesaj rotasını beyan ederken Frontend dört rota daha ekliyordu. Kapı doğru öttü:

```
/panel/icerik/deneyim/[id]   /panel/icerik/deneyim/yeni
/panel/icerik/projeler/[id]  /panel/icerik/projeler/yeni
```

Frontend kimlik zincirlerini raporunda verdi; **dördü de aynı zincirde**: `(panel)`
düzeni + ara katman, çerezsiz istek `307 → /giris?callbackUrl=…`, oturum + 2FA.
Dördünde de `robots: { index: false, follow: false, nocache: true }`.

| Rota | Okuma | Yazma | Ölçülmeyen (Frontend'in beyanı) |
|------|-------|-------|--------------------------------|
| `projeler/yeni` | — | `createProjectAction` | slug çakışmasının **bu rotadaki** hâli (T-034'te liste içi formda ölçülmüştü) |
| `projeler/[id]` | `fetchProjectForPanel` (önbeleksiz, tüm durumlar, MDX + `coverAttachmentId`) | `updateProjectAction` | var olmayan kimlikte 404 dışı davranış; kimlik numaralandırma (cuid tahmin edilemez **varsayıldı**) |
| `deneyim/yeni` | — | `createExperienceAction` | — |
| `deneyim/[id]` | `fetchExperienceForPanelById` | `updateExperienceAction` (+ liste rotasından `deleteExperienceAction`) | bu modelde `status` yok |

**Arşivlenmiş kayıt `projeler/[id]`'de 410 değil, düzenlenebilir** — panelde
`ContentLookup` zarfı yok, bu bilinçli (T-040).

- [ ] Dört rota beyan edildi, kanıt ve "ölçülmeyen" alanları dolu
- [ ] Liste rotalarında sayfa boyutu sabit 25, adresten verilemiyor — beyanda görünsün
- [ ] `pnpm test` yeşil

### 2. ADR-034 — yeni ve seni doğrudan ilgilendiriyor

Backend T-042s'de `redactAuditDiff`'in kapsamını ölçtü; **ben bağımsız bir sonda ile
tekrar ölçtüm ve aynı sonucu aldım:**

```
{ password, passwordHash }        → maskelendi ✓
{ yeniSifre: '…', pass: '…' }     → {"yeniSifre":"SIZAN_DEGER_1","pass":"SIZAN_DEGER_2"}  ✗
{ note: 'şifre: …' }              → {"note":"sifre: SIZAN_DEGER_3"}                        ✗
```

Redaksiyon **alan adı bazlı** — bilmediği adı koruyamaz, ve adı seçen kişi listeyi
düşünmek zorunda kalmaz. **ADR-034 yazıldı:** tek güvenilir koruma sırrı diff'e hiç
koymamak; `redactAuditDiff` bundan sonra hiçbir yerde "koruma" diye anılmayacak,
adı **emniyet ağı**.

Bu varsayım projede **iki kez** kuruldu (T-038 mesaj gövdesi, T-042s şifre).

- [ ] `docs/security/README.md`'de `redactAuditDiff`'ten "koruma" diye söz eden her
      yer **emniyet ağı** olarak düzeltilsin — §8.20 satırı dahil
- [ ] §8.20'nin ⚠️ kalma gerekçesi güncellensin: T-043g'de "merkezî redaksiyon
      yardımcısı yok" yazmıştın; artık asıl gerekçe **redaksiyonun ada bağlı olması**
- [ ] Mevcut kod tabanında `buildDiff` kullanan **ve hassas veri taşıyabilecek** başka
      bir yol var mı — **tara ve raporla**. Varsa düzeltmesi sahibinin, sen bulguyu aç.

### 3. Backend'in açtığı iki talep

**(a) Şifre-değiştirme hız sınırı.** Veri kaynağı hazır: `AuditLog`, `LOGIN_FAILED` +
`diff.context: 'CHANGE_PASSWORD'` (`TOTP_SETUP_RATE_LIMIT` ile aynı kalıp).
`LoginAttempt` bilerek kullanılmadı — o tablo IP başına §8.4 sınırının kaynağı ve
kullanıcı kendi girişinden kilitlenirdi.

- [ ] Politika gerekli mi — **karar senin.** Gerekirse yaz, gerekmiyorsa gerekçesini
      yaz. "Sonra bakarız" geçerli bir cevap değil.

**(b) Oturum geçersizleştirme boşluğu — F6'ya bırakılmadı, kararı bende.**
Şifre değiştirmek ele geçirilmiş bir oturumu **kapatmıyor** (ADR-013 JWT seçti,
sunucuda oturum kaydı yok). Backend uygulamadı ve kolon da eklemedi — doğru karar:
`sessionsValidFrom` eklemek, hiçbir şeyin okumadığı ama oturumların kapatıldığını
düşündüren bir kolon bırakırdı.

Backend iki gerçekçi seçenek verdi: (a) oturum ömrünü 7 günden kısaltmak (§8.3
değişikliği), (b) geçersizleştirmeyi yalnızca Server Action katmanında uygulamak —
**okumaları kapatmaz**, dürüstçe "kısmi" diye adlandırılmalı.

- [ ] **Bu turda uygulama** — ölç ve öner. Ara katmanın Edge'de DB okuyamadığı
      (T-014/K1) doğrulansın; `auth()` jwt callback'inin maliyeti ölçülsün
      (bugün normal istek yolu bilerek DB'ye gitmiyor).
- [ ] Bulgu olarak aç (`docs/security/findings/` **değil** — depo public, R21).
      `docs/security/README.md`'de kayıt.
- [ ] Önerini **T-046** görev kartına dönüştürebileceğim netlikte yaz
