## T-013b — Auth.js v5 bağlantısı: Credentials + 2FA akışı + `LoginAttempt`

**Ajan:** Backend | **Öncelik:** P0 | **Bağımlılık:** T-013a
**Faz:** F1 — Veri & Auth
**PROGRAM.md referansı:** §8.1–8.6, §8.20, §7.2, §12
**İlgili ADR:** 013 (JWT stratejisi, adapter yok, `LoginAttempt` sınırı)

**Amaç:** T-013a'nın primitiflerini Auth.js v5'e bağlayıp giriş akışını tamamlamak.
Kripto tarafı bağımsız test edildiği için bu görevde çıkacak bir sorun bağlantı katmanına
aittir — ayrımın amacı buydu.

**Kapsam (dokunulacak):**
- `src/server/auth.ts` — Auth.js v5 yapılandırması, Credentials provider, JWT callback'leri
- `src/server/auth/login-attempt.ts` — `LoginAttempt` yazma/okuma **servisi** (politika değil)
- `src/server/auth/index.ts` — toplu yeniden ihraç (varsa)
- `src/app/api/auth/[...nextauth]/route.ts` — Auth.js route handler
- `tests/unit/auth/` — giriş akışı birim testleri
- `.env.example` — gerekiyorsa `AUTH_SECRET` açıklaması

**Kapsam dışı (DOKUNULMAYACAK):**
- `src/middleware.ts` — Güvenlik ajanının (T-014). **Bu görevde middleware'e dokunulmaz.**
- **Kilitleme politikası** (kaç deneme / kaç dakika) — Güvenlik ajanının (T-014).
  Bu görev `LoginAttempt` kaydını **yazar** ve `User.lockedUntil` alanına **saygı gösterir**;
  eşikleri belirlemez.
- `src/server/auth/{password,totp,backup-codes}.ts` — T-013a'da bitti, **tüket**
- `prisma/schema.prisma`, `src/lib/schemas/**`
- `prisma/seed.ts` — T-012
- `src/server/services/**` — T-015
- Giriş/2FA **ekranları** — Frontend'in (F3/T-032 sonrası)
- `src/app/**` içinde `api/auth` dışındaki hiçbir şey
- `package.json` — yeni bağımlılık yok

**Kabul kriterleri:**
- [ ] `session: { strategy: 'jwt' }`; PrismaAdapter **yok**, `Account`/`Session` **yok** (ADR-013)
- [ ] Oturum çerezi §8.3'e uygun: `httpOnly`, `secure` (üretimde), `sameSite: lax`, **7 gün**
- [ ] Credentials provider `loginSchema` ile doğruluyor (T-011'den; yeniden yazılmıyor)
- [ ] `verifyPassword(hash, password)` **doğru argüman sırasıyla** çağrılıyor (T-013a/T2a)
- [ ] `decryptSecret` çağrıları `try/catch` içinde; kullanıcıya genel mesaj, ayrıntı loga (T-013a/T2b)
- [ ] `needsRehash()` doğru girişten sonra kontrol ediliyor ve hash sessizce yükseltiliyor (T-013a/T2c)
- [ ] **2FA zorunlu** (§8.1): `totpConfirmedAt` dolu bir kullanıcı TOTP kodu vermeden oturum açamıyor
- [ ] TOTP yerine **kurtarma kodu** kabul ediliyor; kullanılan kod tüketiliyor ve kalan hash'ler kaydediliyor
- [ ] Her giriş denemesi — başarılı ve başarısız — `LoginAttempt`'e yazılıyor; **`emailHash`, ham e-posta değil** (§8.20)
- [ ] `User.lockedUntil` doluysa ve gelecekteyse giriş reddediliyor (politika T-014'te, **saygı burada**)
- [ ] Başarılı girişte `User.lastLoginAt` güncelleniyor
- [ ] **Kullanıcı numaralandırma yok:** "kullanıcı yok" ile "şifre yanlış" ayırt edilemiyor — mesaj ve **süre** olarak (var olmayan kullanıcıda da hash doğrulama maliyeti ödeniyor)
- [ ] Hiçbir log satırında şifre, `totpSecret`, kurtarma kodu veya tam e-posta yok (§8.20)
- [ ] `auth()` yardımcısı Server Action ve Server Component'lerden çağrılabilir biçimde ihraç edilmiş (§8.6 — her action kendi kontrolünü yapacak)
- [ ] JWT içinde hassas veri yok — yalnızca `userId` ve gerekli asgari alanlar
- [ ] Birim testleri: doğru şifre + doğru TOTP · doğru şifre + yanlış TOTP · yanlış şifre · kilitli kullanıcı · kurtarma koduyla giriş · kullanılmış kurtarma kodu · var olmayan kullanıcı
- [ ] Kapsam ≥ %90 (T-013a ile aynı çıta — bu kod kritik)
- [ ] `pnpm lint && typecheck && test && build` temiz; `.env` **olmadan** da build EXIT 0

**Test:** `tests/unit/auth/` altında Vitest. DB gerektiren yollar için Prisma çağrıları
taklit edilir (mock) — `pnpm test` **DB'siz ve `.env`'siz** geçmeye devam etmeli.
E2E senaryoları (§9/3, §9/4) **Güvenlik ajanının** (T-016) — burada yazılmaz.

**Dışarıya sözleşme (raporda mutlaka belirtilecek):**
- `auth()`, `signIn`, `signOut` ihraç imzaları ve nereden import edileceği
- Session/JWT nesnesinin **tam şekli** (Frontend ve Server Action'lar buna bakacak)
- Giriş akışının adımları ve her adımda dönen hata kodu (§7.2 zarfı)
- 2FA akışının Frontend'e yansıyan sözleşmesi: TOTP kodu **hangi adımda** isteniyor, kurtarma kodu nasıl gönderiliyor
- `LoginAttempt` servisinin imzası — T-014 politikayı bunun üzerine yazacak
- `User.lockedUntil` ile etkileşim biçimi
