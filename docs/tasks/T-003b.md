## T-003b — Sürücü adaptörü, tekil Prisma istemcisi, sağlık kontrolü ucu

**Ajan:** Backend | **Öncelik:** P0 | **Bağımlılık:** T-003
**Faz:** F0 — Temel
**PROGRAM.md referansı:** §2, §7.2 Yanıt Formatı, §7.4 Servis Katmanı, §8.20 Loglama, §13.6 Sağlık Kontrolü
**İlgili ADR:** ADR-005 (adaptör onayı), ADR-006 (postinstall), ADR-007 (`prisma.config.ts` mülkiyeti)

**Amaç:** T-003'ün engellendiği noktayı açmak. Adaptör onaylandı; `db.ts` ve `/api/v1/health`
yazılıp F1'in önü açılacak. Ayrıca ADR-006 gereği `postinstall` eklenerek T-004'ün CI hattının
ilk çalıştırmada düşmesi engellenecek.

**Kapsam (dokunulacak):**
- `package.json` — ADR-005 paketleri + ADR-006 script'leri (bu ADR'ler onaydır, ayrıca izin gerekmez)
- `src/server/db.ts` — `@prisma/adapter-pg` ile tekil istemci, açık havuz ayarları
- `src/app/api/v1/health/route.ts` — §13.6, §7.2 zarfı, `force-dynamic`
- `.env.example` — yerel `DATABASE_URL` örneğini 5433'e çek (E4 onaylandı)
- `README.md` — gerekiyorsa kurulum notu

**Kapsam dışı (DOKUNULMAYACAK):**
- `prisma/schema.prisma` — T-003'teki hâli doğru, §6 modeli T-010'da
- `src/app/globals.css`, `src/app/layout.tsx`, `src/app/page.tsx`, `src/components/**`, `src/app/(public)/**`, `src/app/(panel)/**` — Frontend T-002'de çalışıyor olabilir
- `middleware.ts`, `tests/**`, `vitest.config.ts`, `playwright.config.ts`, CI dosyaları — Güvenlik ajanının
- `src/lib/schemas/**`, `src/server/services/**`, `src/server/actions/**` — F1'de
- `next.config.ts`, `tsconfig.json`, `eslint.config.mjs`
- `PROGRAM.md`, `docs/**`
- ADR-005 listesi dışında paket kurmak

**Kabul kriterleri:**
- [ ] `@prisma/adapter-pg` + `pg` dependency, `@types/pg` devDependency olarak kurulu; başka paket eklenmemiş
- [ ] `package.json` script'leri eklendi: `db:up`, `db:down`, `db:migrate`, `db:generate`, `db:studio`, `postinstall`
- [ ] `rm -rf src/server/generated && pnpm install` sonrası istemci yeniden üretiliyor, `pnpm typecheck` temiz (ADR-006 doğrulaması)
- [ ] `src/server/db.ts` → `export const db: PrismaClient` tekil örnek; dev hot reload'ta havuz tükenmiyor
- [ ] `pg` havuz ayarları **açıkça** verilmiş (`max`, `idleTimeoutMillis`, `connectionTimeoutMillis`) — varsayılana bırakılmamış; seçilen değerler raporda gerekçelendirilmiş
- [ ] `GET /api/v1/health` DB açıkken `200` + `{ ok: true, data: { db: "up", uptime, disk, timestamp } }`
- [ ] DB kapalıyken `503` + `{ ok: false, error: { code: "INTERNAL_ERROR", message } }`
- [ ] Hata gövdesinde stack trace, bağlantı dizesi, host adı, kullanıcı adı **yok** (§7.2, §8.20); ayrıntı yalnızca sunucu loguna
- [ ] Uç `force-dynamic`, önbelleğe alınmıyor
- [ ] Sağlık kontrolü DB'ye **hafif** bir sorgu atıyor (`SELECT 1` eşdeğeri), tablo taramıyor
- [ ] `pnpm build` DB kapalıyken de geçiyor
- [ ] `pnpm lint && pnpm typecheck && pnpm build` temiz
- [ ] `.env.example` yerel örneği `127.0.0.1:5433` gösteriyor

**Test:** Otomatik test yazılmaz (altyapı T-004'te). Doğrulama:
`/api/v1/health` çıktısı **DB açık** ve **DB kapalı** iki durumda, HTTP durum kodu + tam gövde
olarak raporda paylaşılır. Ayrıca ADR-006 doğrulaması (`rm -rf` + `install` + `typecheck`).

- `src/server/db.ts` export imzası ve import yolu (servisler buna bakacak)
- Seçilen havuz ayarları ve gerekçesi
- `/api/v1/health` iki gövdenin gerçek çıktısı
