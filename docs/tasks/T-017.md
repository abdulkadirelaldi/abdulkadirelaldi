## T-017 — `/giris` sayfası: iki adımlı kimlik doğrulama akışı

**Ajan:** Frontend | **Öncelik:** P0 | **Bağımlılık:** T-013b
**Faz:** F1 — Veri & Auth
**PROGRAM.md referansı:** §3 (tasarım sistemi), §7.2 (hata zarfı), §8.3, §10.6
**İlgili ADR:** 010 (tema), 013 (2FA + kurtarma kodu)

**Amaç:** Auth.js `pages.signIn` `/giris`'e işaret ediyor; rota olmadan sistem fiilen
kullanılamıyor ve Auth.js kendi varsayılan sayfasına düşüyor. Bu görev T-013b'nin yayınladığı
iki adımlı sözleşmeyi arayüze çevirir.

**Yeni route group:** `src/app/(auth)/` — Frontend mülkiyetinde (§10.1'e eklenecek).
Giriş sayfası ne public layout'a (Navbar/Footer gereksiz) ne panel layout'una (Sidebar
oturum gerektirir) aittir.

**Kapsam (dokunulacak):**
- `src/app/(auth)/layout.tsx` — sade, ortalanmış kabuk
- `src/app/(auth)/giris/page.tsx` — giriş sayfası
- `src/components/auth/login-form.tsx` — iki adımlı form (`'use client'`)
- `src/components/ui/**` — eksik primitif varsa (örn. `FormError`)

**Kapsam dışı (DOKUNULMAYACAK):**
- `src/server/**`, `src/app/api/**`, `prisma/**`, `src/lib/schemas/**` — Backend'in
- `src/middleware.ts`, `src/lib/security/**`, `tests/**` — Güvenlik ajanının (T-014 paralel)
- `package.json`, `next.config.ts`
- 2FA **kurulum** ekranı (QR kod, kurtarma kodu gösterimi) — T-036
- React Bits bileşenleri — T-020

**T-013b sözleşmesi (birebir uygulanacak):**
```
1. adım → signIn('credentials', { email, password, redirect: false })
   ├─ ok                    → panele git
   ├─ code: TOTP_REQUIRED   → kod alanını göster; e-posta+şifreyi FORMDA TUT
   └─ INVALID_CREDENTIALS | ACCOUNT_LOCKED → hata göster

2. adım → signIn('credentials', { email, password, totpCode, redirect: false })
   ├─ ok            → panele git
   └─ INVALID_TOTP  → "kod geçersiz", alanı temizle
```
Kurtarma kodu **aynı alandan** gönderilir: 6 haneli TOTP **veya** `XXXXX-XXXXX`.

**Kabul kriterleri:**
- [ ] `/giris` açılıyor, tek `<h1>`, koyu ve aydınlık temada doğru
- [ ] Form doğrulaması **`loginSchema`** ile (`zodResolver`) — kural yeniden yazılmıyor (§7.3)
- [ ] İki adımlı akış birebir uygulanmış; `TOTP_REQUIRED` sonrası e-posta ve şifre **formda kalıyor**
- [ ] Kod alanının etiketi hem TOTP hem kurtarma kodunu karşılıyor (tek alan, açıklayıcı yardım metni)
- [ ] Hata kodları §7.2 eşlemesine göre **Türkçe** gösteriliyor; `INVALID_CREDENTIALS` "E-posta veya şifre hatalı." — hangisinin yanlış olduğu **belli edilmiyor**
- [ ] Hata mesajı `role="alert"` ile duyuruluyor
- [ ] Gönderim sırasında buton devre dışı ve yükleniyor durumu var
- [ ] Şifre alanı `type="password"`, `autoComplete="current-password"`; e-posta `autoComplete="username"`; kod alanı `autoComplete="one-time-code"`, `inputMode="numeric"`
- [ ] Klavye ile tam gezinilebilir, görünür focus halkası, 360px'te bozulmuyor
- [ ] Hiçbir `.tsx`'te hex yok; token'lar kullanılıyor
- [ ] Giriş başarılıysa `/panel`'e yönleniyor
- [ ] Sayfa `robots: { index: false }` taşıyor
- [ ] `pnpm lint && typecheck && test && build` temiz

**Test:** Otomatik test yazma — `tests/**` Güvenlik ajanının (E2E T-016'da).
Doğrulama elle: iki adım, üç hata kodu, iki tema, klavye, 360px.

**Dışarıya sözleşme:** `(auth)` route group'unun yapısı · `login-form` bileşeninin props'u
(varsa) · hata kodu → Türkçe mesaj eşlemesi (T-016 E2E'de bu metinlere bakacak).
