## T-019 — 2FA kurulmamışsa panele girişte kuruluma yönlendirme

**Ajan:** Güvenlik & Test | **Öncelik:** P0 | **Bağımlılık:** T-018b
**Faz:** F1 — Veri & Auth (**kapanış maddesi**)
**Kaynak:** T-036 → ENGEL-2 · **PROGRAM.md:** §8.1, §8.5

**Amaç:** §8.1 "2FA v1'de **zorunlu olarak açık** gelir" diyor. Bugün 2FA *kurulabiliyor*
ama *zorunlu değil*: seed `totpConfirmedAt`'i boş bırakıyor ve kullanıcı paneli süresiz
2FA'sız kullanabilir. F1'in kabul kapısı bu madde olmadan dürüstçe kapanmaz.

**Kapsam:** `src/middleware.ts` · `src/lib/security/**` · `tests/unit/`

**Kapsam dışı:** `src/server/**`, `src/app/**`, `src/components/**` · `prisma/**` ·
`package.json`

**Kabul kriterleri:**
- [ ] Oturum açmış ama `totpConfirmedAt` boş kullanıcı `/panel/*`'a girdiğinde `/panel/ayarlar/guvenlik`'e yönleniyor
- [ ] `/panel/ayarlar/guvenlik`'in **kendisi** yönlendirilmiyor — döngü yok
- [ ] Çıkış (`signOut`) yolu erişilebilir kalıyor — kullanıcı kurulumu yapmak istemiyorsa çıkabilmeli
- [ ] `/api/v1/panel/*` için yönlendirme değil, **`403 FORBIDDEN`** JSON (T-014/K4'ün aynı gerekçesi: `fetch` yönlendirmeyi sessizce izler)
- [ ] Middleware **DB'ye bakmıyor** — Edge'de Prisma yüklenemez (T-014/K1). Bilgi JWT'den okunuyor; bunun için JWT'ye alan eklenmesi gerekiyorsa **Backend'e talep aç**, kendin ekleme
- [ ] Public rotalar ve `/giris` etkilenmiyor
- [ ] Testler: 2FA'sız oturum → yönlendirme · 2FA'lı oturum → geçiş · güvenlik sayfası muaf · API `403` · oturumsuz hâlâ `/giris`
- [ ] `pnpm lint && typecheck && test && build` temiz

**Dışarıya sözleşme:** yönlendirme kuralının tam ifadesi · muaf yollar · JWT'ye alan
eklendiyse şekli (Frontend ve Backend etkilenir).
