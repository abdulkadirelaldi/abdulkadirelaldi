### Backend'in sözleşmesi hazır (T-038)

**Okumalar** — `@/server/services/contact-message`'ten **doğrudan** çağrılır,
Server Component içinde (§7.1). Action dosyasından yeniden ihraç **edilmedi** ve bu
bilinçli: `'use server'` dosyasından ihraç edilen her işlev ağdan çağrılabilir bir POST
ucu olurdu.

```ts
fetchContactMessages(filter) → { items, total, page, perPage, unreadCount }
fetchContactMessageById(id)  → ContactMessageDto | null   // + message, ip, userAgent
```

Filtre: `{ page, perPage, isRead?, isSpam?, archived?, honeypotHit?, minSpamScore?, q? }`

- `archived` **üç durumlu** — verilmezse arşiv **dahil** hepsi gelir. Varsayılanın arşivi
  gizlemesi "mesajım kayboldu" sorusunu üretirdi.
- `unreadCount` filtreden **bağımsız** — spam sekmesine geçince rozetin değişmesi
  anlamsız olurdu.
- `minSpamScore` `isSpam`'ten ayrı duruyor: `isSpam: false` + `minSpamScore: 20`
  **yanlış pozitif avının yapıldığı yer**. Arayüzde bu ikisini ayrı tut.

**Eylemler** — hepsi `(raw: unknown) => Promise<ApiResponse<T>>`, tekil yoldan import:

```ts
import { markContactMessageReadAction, markContactMessageSpamAction,
         archiveContactMessageAction, unarchiveContactMessageAction }
  from '@/server/actions/contact-message';
import { convertMessageToJobAction } from '@/server/actions/job';
```

`convertMessageToJobAction({ contactMessageId, title })` → `JobConversionDto`
`{ job, client }` — **`client.created` müşterinin yeni mi açıldığını söyler.**
Bu alan arayüz için var: kullanıcı "mevcut müşteriye bağlandı" durumunda **beklemediği
bir kayda bağlandığını fark edebilmeli.** İkisini aynı cümleyle bildirme.

Hata kodları: `UNAUTHORIZED` · `VALIDATION_ERROR` · `NOT_FOUND` · `CONFLICT`
(zaten dönüştürülmüş — `fields.jobId` dolu gelir, **"işi göster" bağlantısı kurdur**) ·
`INTERNAL_ERROR`
